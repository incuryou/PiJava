# PiJava

<img src="assets/icon.png" width="128" alt="PiJava 图标">

**面向 Nintendo Switch 自制软件环境的实验性 J2ME / MIDP 模拟器。**

[English](README.en.md) · [构建](docs/BUILDING.md) · [使用](docs/USAGE.md) · [当前状态](docs/STATUS.md) · [参与贡献](CONTRIBUTING.md)

当前源码版本：`0.2.114-keyui5`。

PiJava 用 C++17 实现虚拟机与宿主功能，并随源码提供自己的 Java 类库。
主要交互界面运行在 Switch 上，围绕手机游戏列表、实体手柄映射和竖屏显示设计。
Linux 桌面程序用于无窗口测试、日志和 PNG 输出。

项目仍在开发中，兼容性需要逐游戏验证。
某个游戏可以进入标题画面，不代表其全部关卡、音频、存档和退出流程都可用。
本次公开首发提供源码，不包含商业游戏，也不承诺提供预编译 NRO。

## 可以做什么

- 从 SD 卡的 `switch/j2me/games` 目录载入 JAR。
- 提供 MIDlet 生命周期、Canvas / GameCanvas、2D 图像与文字绘制等实现。
- 提供 RMS 持久化记录，以及独立的 J2S5 即时存档。
- 提供 MIDI / WAV 音频路径和基于 FFmpeg 的压缩音频解码路径。
- 提供部分 M3G 与厂商扩展 API 实现，实际兼容程度因游戏而异。
- 为每个游戏保存按键映射；每个手机按键最多可绑定三个 Switch 输入。
- 提供三款 Pro 手柄皮肤、三款旧手机皮肤和无边框选项。
- 提供原画、双线性、Scale2x、LCD、CRT 和 ScanlinesDX 显示滤镜。
- 为每个游戏选择 Native、30 或 60 的速度目标，并可显示采样 FPS。

类名或方法存在不等于完整实现相应规范。
M3G、Mascot Capsule 及 Nokia、Samsung、Siemens 等厂商 API 的覆盖都不完整。
字体、编码、声音和游戏自身的时序假设也可能影响结果。

## 平台定位

| 平台 | 用途 | 当前入口 |
| --- | --- | --- |
| Nintendo Switch | 主要使用平台，手柄与图形菜单 | 自行构建 NRO |
| Linux | 开发、回归测试、日志与 PNG 输出 | `build/j2mevm` |
| Windows / macOS | 尚无正式支持的图形前端 | 请勿据此期待桌面 GUI |

Switch 构建需要自行安装正规的 devkitPro 工具链。
本仓库不提供 Nintendo SDK、devkitPro 安装包或游戏资源。

## 快速开始

先阅读[构建文档](docs/BUILDING.md)，准备 Linux 构建环境或 Switch 工具链。
在仓库根目录执行：

```sh
# Linux 无窗口程序
python3 -B tools/build.py

# Switch NRO（需先配置 DEVKITPRO）
python3 -B tools/build.py --switch
```

Switch 的默认产物为 `build/J2me-vm-0.2.114-keyui5.nro`。
编译成功只说明产物完成构建与相应格式检查，不能替代实机测试。

将自行构建的 NRO 放入 SD 卡的 `switch/j2me/`，再放入你有权使用的游戏：

```text
SD:/switch/j2me/
├── J2me-vm-0.2.114-keyui5.nro
└── games/
    └── MyGame.jar
```

通过你的 Switch 自制软件启动环境运行 NRO。
游戏列表只扫描 `games/` 直属目录中的 `.jar`，不递归扫描子目录。
放在 `SD:/switch/j2me/` 根目录的 JAR 不会出现在列表中。

## 游戏列表与显示设置

在游戏列表中，上下选择游戏，`A` 从头启动，`X` 读取已有即时存档。
`L / ZL` 和 `R / ZR` 翻页。
左右只在游戏列表与设置面板之间切换；`B` 返回游戏列表。

在设置面板中，上下选择项目，按 `A` 更改皮肤、滤镜、速度目标或 FPS 开关。
按左右不会直接更改这些值。
速度设置跟随当前选中的游戏；皮肤、滤镜和 FPS 开关是宿主显示设置。

默认皮肤为米白 Pro 手柄。
另外提供蓝色、黑色 Pro 手柄，以及银蓝塑料、黑银金属、复古米灰手机皮肤。
Pro 手柄皮肤上的按键标注跟随当前有效映射。

滤镜只改变最终显示，不改变游戏的 Java 逻辑分辨率。
默认逻辑画布为 `240×320`，Switch 游戏显示区域为固定的 `480×640`。
自定义分辨率和 `.screen` 文件见[使用文档](docs/USAGE.md)。

## 按键映射

游戏运行中按下左摇杆（`L3`），打开“存档与退出”菜单。
按 `L / R` 在“存档与退出”和“修改按键映射”两页间切换。
`L3` 是固定菜单键，不能分配给手机按键。

映射页以手机键盘为入口：

1. 用方向键选择手机按键，按 `A`。
2. 选择三个映射槽之一，按 `A` 打开输入列表。
3. 选择 Switch 输入或“未设置”，按 `A` 确认修改。
4. 按 `+` 将当前映射保存到配置文件。

`B` 返回上一级；`X` 将草稿恢复默认，随后仍需按 `+` 保存。
`Y` 可切换当前游戏映射与全局映射，保存前请查看页脚提示。
仅在列表里选中一个输入还不会写入配置。

默认左摇杆始终发送手机方向键；手机数字 `2 / 4 / 6 / 8` 的默认绑定不包含左摇杆。
十字键按游戏使用的方向模式发送手机方向键或数字 `2 / 4 / 6 / 8`。
右摇杆方向默认绑定数字 `2 / 4 / 6 / 8`，`R3` 默认绑定数字 `0`。
其余默认键位和覆盖规则见[使用文档](docs/USAGE.md)。

## 即时存档与 RMS

“存档与退出”页可保存即时存档、删除即时存档或退出游戏。
删除和退出会再次确认。
回到列表后，按 `X` 尝试继续所选游戏的即时存档。

当前即时存档格式为 **J2S5**；J2S1、J2S2、J2S3、J2S4 会被明确拒绝。
同为 J2S5 也不代表可以任意跨版本、跨类库布局或跨 JAR 混用。
更新程序、替换 JAR 或尝试旧存档前，请备份自己的数据。

RMS 是游戏调用 RecordStore 保存的数据，与即时存档相互独立。
恢复即时存档不等于回滚 RMS，删除即时存档也不等于删除 RMS。
不要将他人的 RMS、即时存档或含个人信息的日志作为公开附件。

## 速度与兼容性

Native、30、60 是运行速度目标，不能保证所有游戏达到对应帧率。
游戏自己的睡眠、逻辑循环、绘制频率和设备负载都会影响结果。
屏幕上的 FPS 是宿主采样指标，不能直接当作游戏逻辑 FPS。

遇到慢速、图形错误或音频异常时，请记录具体游戏版本、JAR SHA-256、
触发场景与设置；用同一场景比较比仅报告“卡顿”更有帮助。

上游 keyui5 工程完成过按键编辑等行为的定点检查，以及 Linux 与 Switch 各一次构建。
公开导出将映射页手机示意替换为原创无品牌资源，并完成本机资产验证；
公开整树尚未重新完成 Switch 构建，仍需使用者构建验证。
上述记录不构成全游戏兼容保证，也不构成全部实机流程验收。
通用的异常恢复与硬卡死兜底尚未完整实施。
已知边界与验证口径见[当前状态](docs/STATUS.md)。

## Linux 诊断示例

Linux 程序没有交互式游戏窗口；它执行指定步数并输出图片与日志：

```sh
J2ME_FRAMES=120 ./build/j2mevm \
  --cp romfs/classes --jar MyGame.jar \
  -o build/game.png --log build/game.log
```

`J2ME_FRAMES` 控制诊断循环次数，并非通用的游戏帧计数器。
请将 `MyGame.jar` 替换为你自己的文件；示例源码与回归夹具用于开发验证。
Switch 生产 ROMFS 不打包示例 JAR。
更多命令与依赖说明见[构建文档](docs/BUILDING.md)。
